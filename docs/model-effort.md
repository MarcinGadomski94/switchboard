# Model and effort in a running session (D31)

Developer ruling D31 (`docs/decisions.md` → *Background work and live model choice*): the session header gets a **model** picker and an **effort** picker. The choices come from the CLI: the models its `initialize` reports and the effort levels the chosen model supports. A change goes to the running process through the control protocol, takes effect from its next turn and shows as a chat step line; the choice is stored on the session and every later spawn passes `--model` / `--effort`. A refusal is shown verbatim and leaves the stored choice unchanged. Sessions without a choice run on the CLI's defaults, exactly as before.

## Server
| Step | What happens | Code |
|---|---|---|
| Spawn | Every spawn (new, resume, a message to a paused session, restart recovery, Attach here, a D16 move) passes `--model <sessions.model>` and `--effort <sessions.effort>` when they are set, after the session id and before `--name`. Neither flag is inherited on `--resume`. | `buildClaudeArgs` (`src/server/supervisor/argv.ts`), `SessionSupervisor.#spawn` |
| `initialize` | D24's handshake hands the reply to the supervisor: `models[]` is read (`parseInitializeModels`: `value`, `displayName` → `label`, `description`, `supportedEffortLevels` → `efforts` unless `supportsEffort` is `false`; entries without a string value and repeats skipped) and stored as `sessions.model_options`. A reply without a usable list keeps the last one. | `LiveRemote.handshake` → `RemoteHost.initialized` (`remote.ts`), `src/core/model-choice.ts` |
| Change | `PUT /api/sessions/{id}/model { model?, effort? }` → `SessionSupervisor.setModel`. A field left out keeps the stored value; `null`, blank or `"default"` (model) = the CLI's default (stored as `NULL`). Changes of one session run one at a time. A choice equal to the stored one does nothing. | `api/sessions.ts` (`parseModelInput`), `supervisor.ts` |
| Check (422) | While the session's list is known: the model must be one of its values; the effort one of the chosen model's levels (a model without levels takes none). While it is unknown: a model name (`[A-Za-z0-9][A-Za-z0-9._:-[]/@]*`, ≤ 100 characters, never a leading `-`) and an effort of `claude --help`'s choices (`low, medium, high, xhigh, max`). Nothing is sent or stored. | `checkModelChoice` |
| Live | When the session has a live process that is not being stopped: `set_model` (the model or `"default"`) when the model changed, then `apply_flag_settings {effortLevel}` when the effort changed; each reply is awaited (30 s). The process is not restarted. | `#setModelNow`, `#modelRequest` |
| Refusal (502) | An error reply → `502 { error: "model-failed", message: <the CLI's text, verbatim> }`; no reply in 30 s says so. Nothing is stored and nothing more is sent. If the CLI took the model but refused the effort, the model **is** stored (the process runs on it) and the effort is not. Each refusal is also an `error` step line: `Could not change the model: <text>` / `Could not change the effort: <text>`. | same |
| Not live | No live process (paused, ended, detached), or it ended while a request waited: the choice is only stored; the next spawn passes it. | same |
| Step line | Every stored change is a `model` event (kind `text`, payload `{type:"model", action:"changed", model, effort, live}`) labelled `Model: <the CLI's displayName, else the value> · effort: <level, else default>`, e.g. `Model: Opus 5.5 · effort: high`, `Model: Default (recommended) · effort: default`; then `sessionUpdated`. | `modelStepLabel`, `#recordModel` |

`Session.model` (so also SessionDetail and `sessionUpdated`) = `{ current, effort, available }`: the stored model and effort (`null` = the CLI's default) and the stored list (`[{ value, label, description?, efforts? }]`, `null` until a process reported one). It is `null` for a session with no model information at all: Switchboard never ran a process for it (`remote_available` is NULL, D24) and nothing is stored, i.e. the demo seed.

## UI
- **The picker** is the first header action (`ModelPicker.tsx`, `session-header.ts` → `modelPicker`): a button in the header actions' style (12 px, 1 px `--border-control`, 6 px radius) reading `<model> · <effort> ▾`: the model's short label (the CLI's `displayName` without a trailing parenthetical: `Default`, `Opus 5.5`), then the effort when one is chosen (`Opus 5.5 · high`). It keeps one line and never shrinks.
- It opens a popover (a card like the Remote one) with the **model** picker (the models in the CLI's order: ✓ + name + the muted description, the chosen one on `--bg-selected-row`) and the **effort** picker (`Default` + the chosen model's levels as pills, the chosen one on the primary tokens), and a note on when a change applies ("from its next turn" while live, "when the session runs again" otherwise). The effort picker hides when the model has no levels (Haiku).
- A pick calls the route at once. A model pick keeps the effort when the new model has that level, else sends `effort: null` (Default), so the server never has to refuse it. A refusal shows the server's text (the CLI's, verbatim) in the popover (`model-error`); the chat shows the step lines.
- While no process of the session has reported its models (`available: null`), the button shows the stored choice, **disabled** (0.45 opacity), with the reason as its tooltip ("No claude process of this session has reported its models yet: …"). A paused session whose list is known stays enabled (the change is stored for the next start).
- Esc, a click outside or ✕ closes the popover; switching sessions closes it.
- Sessions without model information (`model: null`, the demo's) show no picker, so the prototype's header and every visual spec are unchanged.

## fake-claude
`docs/fake-claude.md` → *Model and effort*: `initialize` lists the recorded models (`FAKE_CLAUDE_MODELS=none` leaves the list out); `set_model` and `apply_flag_settings` answer as probed (a bare success, `Model '<x>' not found` / `catalog_unknown`); `FAKE_CLAUDE_SET_MODEL_ERROR` / `FAKE_CLAUDE_EFFORT_ERROR` refuse them with a given text; `get_settings` and later `system/init` lines echo the choice; `--effort` is accepted; `FAKE_CLAUDE_LOG` records every spawn's argv, so tests assert `--model` / `--effort`.
