# Solutions: the workspace scanner (M6.1) and the Solutions view (M6.2)

How Switchboard finds a folder's solutions and decides which ones sessions may write to. The pure rules are in `src/core/workspace-rules.ts`; the file-system walk is `WorkspaceScanner` in `src/server/solutions/scanner.ts`, one per workspace folder; `LiveSolutions` (`src/server/solutions/live.ts`, the real `SolutionsProvider`, `docs/lanes.md`, wired in `src/server/main.ts`) scans the folder it is asked for. It serves `GET /api/solutions?folder=` and the read-only check of `POST /api/sessions`. M6.2 fills the live fields of each row (*Live fields* below) and renders the view (*The view* below); M6.3 adds conflicts and the "Move … to worktree" action (*Conflicts* below).

**D14: one folder at a time.** There is no configured workspace root. `GET /api/solutions?folder=<id>` scans the saved folder with that id (or the folder path of a saved folder or of a session); without `folder`, the default folder (`docs/folders.md`). A **workspace** folder is scanned as below with its own router. A **repo** folder is one group named after the repo (`<repo>/`, editable) with its one solution: `name` = the repo's folder name, `path` = the folder, `relativePath` empty, type `Repo` (shown under All), its checkout's branch, and `codebaseMemory` `unknown` (a repo has no workspace dirty list). Refusals: `409 no-folder` (nothing saved), `404 not-found` (unknown folder), `409 folder-missing` (the folder is gone from disk).

The scanner is read-only: it reads `<root>/AGENTS.md` of its folder and lists folders. It writes nothing, runs no process and never follows a symlink. Tests build fixture workspaces in temp folders and never scan the real workspace.

## Folder rules
The rules come from two sources, merged per top-level folder.

**Baseline.** The layout the handoff documents (ARCHITECTURE → *Workspace rules*, "from the router AGENTS.md"):

| Folder | Rule | Solutions are | Filter pill |
|---|---|---|---|
| `microfrontends/` | editable | each child | Web |
| `mobile/` | editable | the folder itself | Mobile |
| `nugets/` | editable | each child | NuGet |
| `microservices/` | editable | each child | Backend |
| `functions/` | editable | each child | Backend |
| `other/` | on request (gap #15) | each child | Other |
| `deprecated/` | read-only | each grandchild (`deprecated/<type>/<repo>/`) | Read-only |
| `infrastructure/` | read-only | the folder itself | Read-only |

**The router `AGENTS.md`** at the workspace root. Every list item whose first token is a backticked folder ending in `/` is a folder rule: `` - `mobile/` — … ``, `` - `microfrontends/<repo-name>-front/` — … ``, `` - `deprecated/<type-group>/<repo-name>/` — … `` and the bold form `` - **`other/` is non-product, edit-on-request.** … ``. Items that start with anything else, files (`` `mobile/AGENTS.md` ``), hidden folders, table rows, numbered items and fenced code are ignored.
- **Rule** from the item's words (its line plus indented continuation lines): "read-only" / "read only" or "never modify / never edited" → read-only; else "on request", "on explicit developer request", "edit-on-request", "explicitly directs" or "only when the developer …" → on request; else editable. Read-only words win over on-request words in one item.
- **Depth** from the segments after the folder: `mobile/` = 0, `microfrontends/<repo-name>-front/` = 1, `deprecated/<type-group>/<repo-name>/` = 2 (capped at 3).
- Several items for one folder merge: the strictest rule, the deepest depth. The real router has three for `deprecated/` (Layout, Naming convention, Cross-cutting rules).

**Merge.** Baseline folders keep their order. The router can make one stricter (read-only > on request > editable) or deeper, never looser: a router that stopped saying `other/` is on request would still leave it on request. Folders only the router names are added after them, in the router's order, with its rule and depth and the pill Other (Read-only when read-only). Without an `AGENTS.md` the baseline alone applies (`router.found` = false in the scan).

## Walking the folders
For each folder at its depth:
- Only real directories count: files, symlinks and hidden entries (`.git`, `.idea`, `.claude`, `.worktrees`) are skipped. A top-level folder that is a symlink counts as absent.
- **Gap #16:** a folder whose `.git` is a **file** (a git worktree such as `web-front-wt-free-talk`, or a submodule) is skipped, at every level, the single-solution folders included.
- A folder whose `.git` is a directory (a main checkout) is a solution wherever it sits. So `deprecated/mobile/`, which the router lists as a repo directly under the type level, is one solution, not a type group.
- Any other folder is a solution at the last level (`git: false` in the scan, a slot the router defines that is not cloned yet) and a grouping folder above it.
- Nothing below a solution is scanned (e.g. `other/switchboard/.worktrees/`).

`WorkspaceScanner.scan()` returns the whole scan (`WorkspaceScan`: the router file with its line count for the setup wizard, then every folder with `exists`, `inRouter` and its solutions with `name`, `relativePath`, absolute `path`, `git`) for later items (M5.3 wizard, M8.2 Settings scan table).

## `GET /api/solutions`
`SolutionGroup[]` (`src/core/api.ts`):
- One group per writable folder that has solutions, `folder` = `microfrontends/`, `mobile/`, …; `note` empty, or **"on request only"** for an on-request folder (`other/`, gap #15; visible under the All filter since its pill is Other).
- Then **one** group `folder: "read-only"` with every read-only folder's solutions and the note built from the folders that have solutions: `deprecated/ · infrastructure/ · never edited` (the prototype's copy).
- Groups without solutions are left out. Solutions are sorted by name (case-insensitive).
- Each solution: `name` = its folder name, `path` = its absolute path in the current OS's form (gap #17; the detail panel shows it), `relativePath` = its path from the root, `/`-separated (M6.2; the view derives the header's root from it), `type` = the folder's pill, `rule` = the folder's rule. The scan alone (`toSolutionGroups`) leaves the live fields neutral: `status: "idle"`, `phase: "—"`, `changes: "—"` (`"locked"` for read-only, the prototype's copy), `flag: ""`, `conflict: false`, `conflictSessions: []`, `branches: []`, `ledger: null`, `artifacts: []`, `codebaseMemory: "unknown"`; `LiveSolutions` fills them (below).
- D14: `409 {error:"no-folder"}` while no folder is saved, `404 {error:"not-found"}` for an unknown `?folder=`, `409 {error:"folder-missing"}` when the folder is not a folder any more. Without a passed `providers.solutions` (tests), the route builds `LiveSolutions` over the store, the session diff and the worktree manager's resolution itself; demo mode serves the demo provider (which ignores the folder).

The scan runs on every request (a workspace has a few dozen folders); nothing is cached.

## Live fields (M6.2)
`LiveSolutions` (`src/server/solutions/live.ts`, the real `SolutionsProvider` wired in `main.ts`) runs the scan, then fills each row from the database and the solution folders. The pure rules are in `src/core/solutions-live.ts`. It reads only: the database, `<solution>/.git/HEAD`, `<solution>/phase-ledger.md`, `<solution>/mobile-followups/`, `<root>/.claude/.codebase-memory-dirty`; git runs only through the session diff (the worktree manager, gap #10). Nothing is cached; a file that cannot be read leaves its field neutral and is reported through `onError`.

- **Which sessions work on a row.** A live worktree belongs to the row whose canonical path is the worktree's `repoPath` (worktree rows store canonical paths). A session works **in place** on a row when it is open (`endedAt` is null: live, paused or detached), lists a solution that resolves to that row the way the worktree manager resolves it, and has no worktree for it. D14: the name resolves **in the session's own folder**: for a session of the folder shown, in memory (a workspace: `solutionCandidates`, `<root>/<name>` or `<root>/<group>/<name>`, exactly one git checkout among the writable rows, else no row; a repo: its one row); for a session of another folder, through the worktree manager's `resolveRepo(solution, folder)`, matched to a row by canonical repo path (so a workspace session in place in `other/switchboard` shows on the repo folder `switchboard`, and conflicts count writers from every folder). Read-only rows never get sessions.
- **`branches`** (chips and branch cards), in this order: each live worktree (`branch`, `worktree` = its path, given in the configured root's form when it sits next to the repo so the UI can print `../<folder>`, `owner` = its session's name, `status` = the session's status; a worktree whose session is gone: owner `—`, `idle`), then each in-place session (`branch` = the checkout's branch, `worktree: null`, the session's name and status). A row nobody works on shows its checkout's branch with owner `idle` (the prototype's `⎇ main · idle`); a folder without git shows no chip. The checkout's branch comes from `.git/HEAD` (`ref: refs/heads/<branch>`, or the first 7 characters of a detached commit), not from a git process.
- **`status`** (the row's dot): the most urgent status among the sessions on its branches, `need` > `fail` > `run` > `paused` > `done` > `idle`; `idle` without sessions and for read-only rows. The header's "n active" counts rows whose status is not `idle`.
- **`phase`**: the phase ledger's phase (`mixed` when its entries differ), else the open sessions' phases (`UI-first` / `integration` / `mixed`), else `—`; `—` for read-only rows.
- **`changes`**: the lines the sessions' diffs add to the row (gap #10: each worktree against the merge-base with its base branch, in-place solutions against HEAD, untracked files included), summed over the sessions that have a worktree in the repo or work in place on it: `+<added>`; `−<removed>` when lines are only removed; `—` without changes; `locked` for read-only rows. A diff that fails counts nothing.
- **`ledger`** (gap #12): `<solution>/phase-ledger.md` parsed leniently, `null` without the file. Table rows: the phase cell holds only `UI-first` / `integration` (any case, `ui first` too), the interface is the first non-empty cell before it, the seam the non-empty cells after it joined with ` · `; header and separator rows are skipped. List items: the interface is the text before the first phase word, the seam the text after it, separators (`→`, `->`, `=>`, `:`, dashes, `|`, `,`, `·`) trimmed. Backticks and bold marks are removed; headings, prose, items without a phase word or without an interface and fenced code are skipped.
- **`artifacts`** ("Artifacts & follow-ups"): the sessions' artifacts whose `solution` is the row's name (gap #9, every type, newest first, one per type + name), then the row's `mobile-followups/*.md` files that are not listed yet (type `FOLLOWUP`, no meta, no session). The follow-up files' format is not specified, so no "n pending" is derived.
- **`codebaseMemory`**: `dirty` when a line of `<root>/.claude/.codebase-memory-dirty` concerns the row, else `fresh`; `unknown` when the file exists but cannot be read (a missing file means nothing is dirty). The rules are M6.4's, *Codebase-memory freshness* below.
- `conflict`, `flag` and `conflictSessions`: M6.3, *Conflicts* below.

Demo mode serves the same fields from `src/server/demo/data/solutions.json` (the prototype's `SG`, `LED`, `ARTS` and dirty list, paths under its root `D:\acme`, `docs/demo.md`).

## The view (M6.2)
`src/web/views/SolutionsView.tsx` + `solutions.css` (SPEC → Solutions; the prototype's inline styles as classes over the SPEC tokens), with the pure view logic in `solutions-format.ts`:
- Header: "Solutions" + `<root> · <n> solutions · <n> active` (the root is the first row's `path` minus its `relativePath` segments; nothing while the list is not loaded). Filter pills All, Web, Mobile, NuGet, Backend, Read-only; `other/` rows (pill Other) show under All only (gap #15).
- Groups by folder (the note in `#5a5955`), the read-only group at 60% opacity. Row grid `minmax(130px,190px) minmax(240px,1fr) 80px 54px`: status dot + name (flag on a second line, amber for a conflict), branch chips `⎇ branch · worktree folder · dot · owner` (ellipsized), phase, changes. Rows are buttons (click, Enter, Space).
- Detail panel of the selected row (default: the first row; the selection survives filtering): path, name, "Branches & worktrees" cards (branch, `../<worktree folder>` next to the repo / the full path elsewhere / `in place`, owner with its status dot), "Phase ledger" (phase in amber for UI-first, blue for integration; without a ledger one row `— · <row phase> · no phase-ledger.md` (gap #12), with an empty one `phase-ledger.md has no entries`), "Artifacts & follow-ups" (type tag, name, meta; none → `INFO · No artifacts`), and the freshness line: `codebase-memory · edited by agents since last index` (amber) / `codebase-memory · indexed · fresh` (green) / `codebase-memory · freshness unknown` + "open Codebase Memory ›", which opens the tool named Codebase Memory, or Settings → Embedded tools while none is configured.
- Live: `sessionUpdated` reloads the list (at most once a second), `worktreeRemovable` reloads it at once. A 409 `no-folder` shows "No folder is saved yet. Add a workspace or a git repository in Settings → Folders." (D14), a 409 `folder-missing` "This folder is not there any more. Pick another one above, or remove it in Settings → Folders.", other errors the server's message; an empty workspace "No solutions found in the workspace."
- **Folder switcher** (D14, `docs/folders.md` → *UI*): with two folders or more to choose from (the saved ones, then the folders sessions use that are not saved), the header's path is a dropdown (`solutions-folder`) followed by `· <n> solutions · <n> active`; with one it reads as before. The selection is `?folder=` in the URL (reload keeps it; the default folder has none). A repo folder shows one group `<repo>/` with its one row.
- The conflict card with "Move … to worktree" (M6.3) sits between the path/name and "Branches & worktrees" (*Conflicts* below).

## Conflicts (M6.3)
ARCHITECTURE → *Workspace rules*: "Two sessions writing the same repo → each must have its own worktree, or a conflict warning appears" (the router: `isolation: 'worktree'` for parallel writers in the same repo). The pure rule is `repoConflict` in `src/core/conflicts.ts`; `LiveSolutions` feeds it per row.
- **Who writes a repo.** The open sessions (`endedAt` null: live, paused or detached) on the row as *Live fields* defines them: each session with a live worktree of the repo (`isolated`), and each session working in place on it (resolved the worktree manager's way, no worktree there). A session whose process ended (`done` / `fail` after exit) no longer writes; a paused or detached one still does (a terminal may be writing). Read-only rows never have writers.
- **Conflict** = two or more distinct writers and at least one of them **in place**. Two worktree sessions are fine; one session alone in the checkout is fine; a worktree session plus one in place is a conflict (the prototype's `mobile` case: `free-talk-feature` in `mobile-wt-free-talk-feature`, `button-rollout` in place).
- **Wire** (additive on `Solution`): `conflict: true`, `flag: "⚠ shared working tree"` (the prototype's row flag, amber), and `conflictSessions`, every writer oldest first (then by name): `{ sessionId, name, isolated, repo, attached }`. `repo` is the `{repo}` for `POST /api/solutions/{repo}/isolate`: the solution string the session itself lists (or its worktree's `repo`), so the worktree manager's "already isolated" check and the session diff match it. Without a conflict: `conflict: false`, `flag: ""`, `conflictSessions: []` (the "contract source" flag of the prototype is not derived: no rule for it).
- **The card** (`SolutionConflictCard.tsx`, pure logic in `solutions-conflict.ts`): the prototype's `sd.warn` copy with the writers' names: two → "`a` and `b` both write to `<relativePath>/` in one working tree. Your AGENTS.md requires isolation: 'worktree' for parallel writers in the same repo."; three or more → "`a`, `b` and `c` all write to …". One primary button **"Move `<name>` to worktree"** per writer in place, oldest first; a detached writer's button is disabled (isolating it answers 409 `detached` until it is attached again; its title says so). A click posts `POST /api/solutions/{repo}/isolate { sessionId }` (gap #2, `docs/worktrees.md` → *Isolate*: the worktree `../{repo}-wt-{session}` on `session/{session}`, then the session is paused and resumed with the move message; the developer's checkout is never touched), disables the buttons while it runs, reloads the list when it answers and shows the server's message under the buttons when it refuses.
- **Moving one writer may not clear the conflict:** with two sessions in place, the one left in place still shares the repo with a worktree session, so the card stays with one button until it is moved too.
- **Sidebar:** the Solutions nav badge "`n` conflict(s)" (amber, `conflictCount` = rows with `conflict`) reloads `GET /api/solutions` on `sessionUpdated` (at most once a second, `useThrottled`) and on `worktreeRemovable`, so it follows sessions starting, ending and moving.
- **Demo** (`solutions.json`): the `mobile` row carries `conflictSessions: ["free-talk-feature", "button-rollout"]`, the two names of the prototype's `sd.warn`; `isolated` = the branch has a worktree folder. In demo mode the button calls the real worktree manager, which has no workspace root there, so it shows the refusal; the prototype's "moved" state (`conflictFixedBranch`) is not replayed.

## Codebase-memory freshness (M6.4)
The pure rules are in `src/core/codebase-memory.ts`; the file is read by `readDirtyList` in `src/server/solutions/codebase-memory.ts` (async, read-only). Switchboard never writes the file and never runs codebase-memory.

**The file.** The workspace's dirty-tracker hook (`.claude/hooks/cm-mark-dirty.js`, a PostToolUse hook on Edit / Write / MultiEdit / NotebookEdit; read once for this rule, never touched) writes `<root>/.claude/.codebase-memory-dirty`. For a file edited at `<root>/<category>/<first folder>/…`, with a category from its list (`microfrontends`, `microservices`, `functions`, `nugets`, `mobile`, `other`, `infrastructure`), it adds the codebase-memory **project id** of `<root>/<category>/<first folder>`: the absolute path with `\` turned into `/`, trailing slashes dropped, every run of `:` `/` `\` turned into one `-`, leading and trailing `-` removed (`/Users/me/Acme Corp/workspace/nugets/auth-nuget` → `Users-me-Acme Corp-workspace-nugets-auth-nuget`; `D:\ws\mobile\src` → `D-ws-mobile-src`). One id per line, sorted, no times. An agent that re-indexes a project removes its line (the router's *Code-intelligence MCP usage*). The hook ignores edits elsewhere (`deprecated/`, files directly in a category folder).

**Reading** (`dirtyLines`, `parseDirtyFile`, `readDirtyList`): a byte-order mark is removed; `\n`, `\r\n` and a lone `\r` end lines; lines are trimmed; blank lines and repeats (case-insensitive, the first spelling kept) are dropped; file order is kept. A missing file or `.claude/` folder = an empty list (`missing`); anything else that fails (a folder in its place, no permission) = `unreadable` (every row `unknown`, reported through `onError`).

**Naming a line** (`dirtyProject`). The hook resolves the root it sees (`CLAUDE_PROJECT_DIR`), which may be the configured root or its real path (a symlinked root, `/var` → `/private/var` on macOS), so the reader matches both forms (`workspaceRootForms`). A line that is a root form's id followed by `-<category>-<folder>` (the category compared case-insensitively; categories contain no `-`, so the rest, dashes included, is the folder) names `<category>/<folder>`. Any other line (another workspace, an unknown category, the root or a category alone) names no folder. Ids compare case-insensitively (the developer's file systems are).

**A row is dirty** (`concernsSolution` / `solutionFreshness`) when some line
- is exactly the row's own project id under one of the root forms (so any codebase-memory id counts, whatever wrote it), or
- names the row's folder, a folder inside it, or a folder that contains it (on `/` boundaries). *Inside* covers the whole top-level solutions: the hook records edits in `mobile/` as `mobile/<first folder>` (`…-mobile-src`), and in `infrastructure/` likewise. *Contains* covers a solution nested deeper than the hook's `<category>/<folder>` granularity (`microfrontends/group/x-front` when the line names `microfrontends/group`): the edit may have been in it, so it is not called fresh.

A longer sibling is another project (`nugets/auth-nuget-v2` does not make `nugets/auth-nuget` dirty), and `deprecated/mobile` is not `mobile`.

**The Codebase Memory strip** (SPEC → Tools: the `.codebase-memory-dirty` projects + "Reindex n now") gets its list from `dirtyTargets(projects, roots, rows)`: one entry per solution that lines concern, named like its Solutions row (`mobile` once, however many `mobile/<folder>` lines), with the lines behind it (the ones a reindex removes); then one per line no solution matches, named after the folder it names (lines naming the same folder share one entry), else the id. A line that concerns several solutions counts for each. Entries keep the order of their first line; *n* in "Reindex n now" is their count. The file holds no times, so none are derived. The strip itself, its route and the reindex session (gap #4) are M8.1's (`docs/tools.md` on the w1-tools lane, which reads the file with its own parser in `src/server/tools/codebase-memory.ts`); the lane merge keeps one reader: that route should serve `dirtyTargets` over `readDirtyList` and the scanned rows.

## Read-only sessions (`POST /api/sessions`, 422)
The validation always applies the static layout check (`isReadOnlyByLayout`: `deprecated/…`, `infrastructure`) to a session in a **workspace** folder. With the scanner it also asks `SolutionsProvider.isReadOnly(solution, folder)` for that folder (`readOnlyCheck` in core). A session in a **repo** folder (D14) has exactly one solution, the repo, and none of these checks apply:
- a solution whose own path starts in a read-only folder is refused (`archive/old-repo` when the router marks `archive/` read-only);
- a bare name is refused when a folder it can resolve to under the router layout (`solutionCandidates`, the worktree manager's resolution: `<root>/<name>` or `<root>/<group>/<name>`) lies in a read-only folder **and exists**.

So a live `mobile` is never refused because the archive holds a `deprecated/mobile/`: a bare name cannot resolve into `deprecated/`. (A provider without `isReadOnly`, like the demo's, is matched by row name as before.)

## Nested checkout (developer ruling 2026-09-28)
A solution folder that is not a git main checkout itself but holds **exactly one** direct subfolder that is (`checkoutOf` in `src/server/solutions/checkout.ts`) stands for that repo. This is the real mobile layout: the router's `mobile/` holds the clone `mobile/acme-app-mobile/`. The row keeps the router's name and folder (`mobile`), and its branches, phase ledger, `mobile-followups/` and worktrees come from the nested repo (`ScannedSolution.repoPath`); the worktree manager resolves the name `mobile` to it, so a worktree is `mobile/acme-app-mobile-wt-{session}`. Hidden folders, symlinks and worktrees (`.git` is a file) never count; with several nested checkouts nothing is picked.
