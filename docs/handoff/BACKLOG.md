## M3 · Inbox & questions
- [x] **M3.1** *(adapted after M0)* Question pipeline on the stdio control protocol (M0.2; `ARCHITECTURE.md` → *Questions and permission requests*). A `control_request/can_use_tool` for `AskUserQuestion` = one batch: `batchId` ← `request_id` (keep `tool_use_id`), one `Question` per `input.questions[i]` with the `question` text, `header`, option labels + descriptions and `multiSelect` stored verbatim; source = the session's main agent (subagents cannot ask; no attribution is inferred from the text). Answering (`POST /api/questions/batch/{batchId}/answers`, 400 unless all are answered) writes one `control_response` line: `behavior:"allow"`, `updatedInput` = the input unchanged + `answers{<question text>: <option label>}`; a `multiSelect` question takes one option, because the contract carries one `answerIndex`. A `can_use_tool` for any other tool = an Inbox permission item (D6: `tool_name` + `input` verbatim, plus `description` / `decision_reason`, attributed to a subagent through `agent_id` → `system/task_started`) with the actions `allow-once` (`allow` + the input unchanged, never `updatedPermissions`) and `deny` (`deny` + a fixed message) via `POST /api/inbox/{id}/actions/{action}`. A `control_cancel_request`, or the process ending while a request is open, makes it **stale**: no response is ever written to it. A stale question batch stays answerable, and its answers (questions and answers verbatim) are sent as a normal user message when the session next runs; a stale permission item closes without a decision. **Oracle:** fixture tests with fake-claude: `ask-2q` → one batch with two verbatim questions, and the `control_response` written equals the recorded answer in `ask-2q.stdin.ndjson` (apart from `request_id`); `ask-multiselect`; `perm-allow` / `perm-deny` through the inbox actions; `subagent-perm` attribution; `ask-interrupt` → stale with nothing written, and a later answer arrives as a user message after resume.
