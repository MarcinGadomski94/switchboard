# Switchboard 2: the v2 theme and the classic theme (D131)

Switchboard 2 ships a new UI, the **v2 theme** (Direction D v3: `docs/design/v2-prototype.html`), as the default, and keeps the 1.x UI as the **classic theme**. Both are one app: the same server, API, `/hub` events and data. Plan: `docs/design/v2-plan.md`; decisions: `docs/decisions.md` → D131; every lane's assumptions: `docs/design/v2-decisions.md`.

## Two themes

- **Which one shows:** this browser's own choice (`localStorage['switchboard.ui.theme']`), else the service's default (`ui.theme` in `GET /api/settings`, default `v2`; `SWITCHBOARD_UI_THEME_DEFAULT` sets another until it is stored). Each phone is a browser with its own choice.
- **No flash:** `src/web/main.tsx` reads the settings (the same read as the pane state, D41) and the stored choice before the first render, and loads the v2 code first when v2 is the one shown. `<html data-ui="v2|classic">` is set before anything paints.
- **Switching** (`src/web/theme.ts` → `themeStore.choose`) swaps the whole UI at once, without a reload. `src/web/Root.tsx` first replaces the address with the other UI's address of the same page (`src/web/v2/routes.ts` → `toV2Path` / `toClassicPath`), so the page stays where both have it.
- **Where:** classic Settings → **Appearance** (`src/web/views/settings/AppearanceSection.tsx`) and v2 Settings › Appearance (`src/web/v2/settings/ThemeRow.tsx`); also the ⌘K palette ("Switch to the classic theme"). Either may also make the current theme the default for new browsers (`PUT /api/settings { "ui.theme" }`).
- **Links:** every classic address still opens its page in v2 (push notifications, paired computers and bookmarks use them): the v2 shell replaces it with the v2 address (`/sessions/a/diff` → `/agents/a/changes`, `/inbox` → `/needs-you`, …).
- **Tests:** the E2E servers default to classic (`tests/helpers/server-process.ts`), so the classic specs are unchanged; a v2 spec opts in with `V2_SERVER_ENV` or `useV2(page)` (`tests/e2e/v2-world.ts`).

## Components (`components/index.ts`)

`Icon` (the prototype's SVG set, `icon-paths.ts`), `Button` (variants primary / default / danger / ghost, `num` for answer keys, `kbd`), `IconButton` (required label, badge), `Kbd`, `Chip`, `StatusBadge` (icon + word + colour for every `V2Status`; `compact` = icon with the word for screen readers), `Card` (`interactive` = focusable, Enter / Space), `Skeleton`, `EmptyState`, `Tabs` (tablist, ←/→), `Segmented` (toggle group), `Menu` / `MenuButton` (⋯; ↑/↓, Home, End, Esc, a disabled item says why), `Popover`, `Dialog` (modal, focus trap), `Sheet` (side sheet, the peek), `Drawer` (side panel without a scrim), `BottomSheet` (phone), `ToastProvider` / `useToast()` (`{ text, undo }`), `Avatar` (initials or icon + status badge), `ComputerTag` (online / reconnecting / offline in words), `Field`, `TextArea`, `Select`, `Checkbox` (44 px row), `Switch`. Every control has a focus ring and is ≥ 44 px on touch screens; overlays close on Escape and return focus. Overlays render through `Portal` into the v2 root's `.v2-overlays` layer (a blurred or scrolling ancestor would otherwise shift `position: fixed`); use `Portal` for any new floating element.

## Shared modules

- **`shared/needs-you.ts`** (logic in `needs-you-store.ts` and `needs-you-model.ts`): one live list of everything that waits for the developer, merged from the Inbox (questions, permissions, waiting-for-you turns, plan steps stopped / ready / pick code projects, failed routines, memory proposals, alerts; this computer's and the paired ones'), Team's requests (access, job descriptions, gates, budgets) and usage (out of usage, paid extra). Each `NeedsItem` has `kind`, `source`, `agent`, `crew`, `computer` and what answering needs. Hooks: `useNeedsYou()` (`items`, `loaded`, `error`, `answered`, `pending`, `errors`), `useNeedsYouCount()`, `useNeedsItemsOf(sessionId)`. `needsYouStore.answer(item, action, where)` hides the item everywhere at once and sends it after a 5 s Undo window (`needsYouStore.undo(key)`); a refusal brings it back with the reason.
- **`shared/AnswerCard.tsx`**: `<AnswerCard item variant="queue|chat|popover|phone" where="home|needs|chat|board|crew|phone" />` answers any item (single-choice, multi-select with Choose any + Other…, batches, approvals, asks with reply and Not waiting, ready for approval with Combine / Send back / View changes, stopped, notes, access requests, job descriptions, failed routines, pick code projects, alerts); keys 1–9 on a focused card; the compact line once answered (`AnsweredLine`, `<AnswerSlot itemKey item />`). The pure part: `answer-model.ts` (`cardButtons`, drafts, `summaryOf`, `answeredFromServer`).
- **`shared/agent-row.tsx`**: `AgentRow` (chat-style row), `AgentCard` (Working now), `ActivityLine`, `AskPreview`, `AgentComputerTag`, `UnreadDot`, `DraftMark`; pure `agent-line.ts` (`agentStatusOf`, `agentLine`, `agentName`).
- **`shell/shortcuts.ts`**: `useShortcut('side-panel' | 'folder-tree', handler)` for ⌘. and ⌘\ (the shell emits them); `shortcutList()`.
- **Openers:** `openNew({ kind, text?, prefill?, machine? })` (`new/`), `openPalette(query?)` (`palette/`), `openShortcuts()` (`shell/ShortcutsDialog.tsx`), `openPeek(sessionId)` (`agent/`: the agent's peek sheet; the shell renders its `PeekHost`).

## Shell

- **Desktop (≥ 1280 px):** a 232 px rail: brand, Home · Agents · Projects · Crews · Results · Settings (each with its Needs-you count), **Pinned** (the shared sidebar layout's pins, D71), the computers and phones at its foot. The top bar: Search (the ⌘K palette) · the Search page (⌘⇧F) · the shortcuts list (`?`) · a computer offline or reconnecting · the **status pill** (the active account's usage, this computer's power, the computers; its popover lists every account with paid extra usage, every computer with CPU, RAM, power and background apps, and Reconnect now) · **Needs you** with its count · **+ New**.
- **Tablet (768–1279 px):** an 84 px rail, icons with their labels under them; no pins or foot.
- **Phone (≤ 767 px):** no rail; a compact top bar (brand, the pill's usage, Search, + New) and bottom tabs **Home · Needs you · Agents · Results · More** (More: Projects, Crews, Tasks, Routines, Notes, Insights, Settings, the usage and the computers).
- The breakpoints are `docs/responsive.md`'s (`src/web/shell/viewport.ts`).

## How to add a v2 page

1. Find the area folder (or ask the orchestrator for a new route: routes are lane F's). Export the page from its `index.tsx`; the router already mounts it.
2. Use the words in `glossary.ts` (add any missing word there), the base components, `useV2Router()` / `<V2Link>`, and the shared modules above. Read data with the existing API clients and hub hooks.
3. Style under `.sb2` with `--v2-*` tokens; check light and dark, 390 × 844, 768 and 1280+; status as icon + word + colour; 44 px targets; reduced motion.
4. Test: pure logic in `tests/web/v2-<area>.test.ts` (no JSX / DOM imports there: the Node typecheck has no DOM), E2E in `tests/e2e/v2-<area>.spec.ts` with `tests/e2e/v2-world.ts`, headless, no `channel`.
5. Record any decision you had to make in `docs/design/v2-decisions.md`.
